# 설계: 성능 아키텍처 — 연결당 비용과 전달당 비용을 바닥까지

- 상태: 초안 (2026-10-16). 각 단계는 측정으로 효과를 확인한 뒤 채택한다. 큰 구조 변경(전송 재작성, 코어별 샤딩)은 ADR을 따로 쓴다.
- 관련: [ROADMAP](../ROADMAP.md) M5, [BENCHMARKS](../BENCHMARKS.md), [ADR 0002](../adr/0002-transport-agnostic-out-frame.md), [ADR 0005](../adr/0005-session-transport-seam.md), [Hot Lane over WebTransport](hot-lane-over-webtransport.md)

## 0. 목표와 원칙

성능은 세 가지 비용으로 나눠 다룬다. 각각 다른 구조가 지배한다.

| 비용 | 무엇이 지배하나 | 지금 (측정) | 목표 (검증 전 가설) |
|---|---|---|---|
| **유휴 연결당 메모리** | 연결마다 상시로 잡는 버퍼·자료구조 | 22~23 KB (사용자 1명 조건 — 실제보다 낙관적, §1) | **≤ 8 KB** |
| **전달당 CPU** (고부하) | 시스템 콜·task 깨움·복사 횟수 | 4.7 µs → 쓰기 합치기 후 3.6 µs (216만 전달/s, 8코어) | **≤ 1.5 µs** |
| **꼬리 지연** | 큐 적체, 큰 룸 팬아웃, 코어 간 이동 | p99 18~30 ms @ 216만/s | p99 ≤ 10 ms @ 216만/s |

원칙:
1. **측정 먼저.** 프로파일(§10)로 비용이 어디서 나는지 확인한 뒤 고친다. 해시맵을 고쳐서 얻는 건 수신자당 수백 ns지만, 시스템 콜과 task 깨움은 µs 단위다.
2. **유휴 연결은 거의 공짜여야 한다.** 버퍼는 "쓸 때 빌리고 다 쓰면 돌려주는" 방식으로 바꾼다. 연결에 상시 붙는 것은 소켓과 작은 상태뿐이어야 한다.
3. **같은 바이트는 한 번만 만든다.** 서버→클라이언트 WebSocket 프레임은 마스킹하지 않으므로, 같은 메시지의 와이어 바이트는 모든 수신자에게 **완전히 같다**. 직렬화·프레이밍을 한 번 하고 같은 버퍼를 N개 소켓에 쓴다.
4. **코어 간 공유를 피한다.** 메시지마다 모든 코어가 같은 원자 변수·락을 건드리면 캐시 라인이 코어 사이를 오간다. 카운터와 상태는 코어(샤드)별로 나눈다.
5. **경계(ADR 0005)를 지킨다.** 전송 재작성은 `SessionTx`/`SessionRx` 구현 교체로 끝나야 한다.

## 1. 현재 비용 모델

### 1.1 유휴 연결당 메모리 (소스 확인 + 계산, 측정 22~23 KB와 합이 맞음)

| 항목 | 크기 | 근거 |
|---|---|---|
| tungstenite 읽기 버퍼 | **8 KB** | `ReadBuffer`: `Vec::with_capacity(4096)` + `Box<[u8; 4096]>` 청크(tungstenite 0.24 `buffer.rs`). 연결 내내 유지 |
| tungstenite 쓰기 버퍼 | 0 → 최대 메시지(묶음) 크기 | `out_buffer: Vec<u8>`, 한 번 커지면 줄지 않음 |
| **세션의 룸 집합 `DashSet`** | 약 1.8 KB (8코어 고정) ~ 7 KB (24스레드) | 샤드 수 = **프로세스가 쓸 수 있는 CPU 수**(CPU 고정 반영) × 4 → 2의 거듭제곱, 샤드당 약 56 B. 룸에 들어간 세션마다 1개. **P0-c에서 제거** |
| 사용자별 `DashSet` 2개 (`user_index`, `user_to_rooms`) | 측정 +3.5 KB/연결 (8코어 고정) | 연결마다 다른 사용자로 재면 드러난다(이전 벤치마크는 전 연결이 `user:dev`). **P0-c에서 제거** |
| tokio `mpsc` 송신 큐 | 약 1.3 KB | 생성 시 슬롯 32개 블록을 즉시 할당(`list::channel` → `Block::new`), `OutFrame` 약 40 B |
| tokio `mpsc` 종료 요청(`ctl`, 용량 1) | 약 1.8 KB | 용량과 무관하게 32슬롯 블록 × `CloseSpec` |
| 쓰기 합치기 `Vec` (T0, 미커밋) | 2.5 KB → 부하 시 증가 | A/B 측정: +2.8~5.3 KB/연결 → **버퍼 없는 방식으로 교체 (§3.4)** |
| 타이머 2개 (ping, idle), task, 세션 상태, hyper 업그레이드 잔여 | 약 2~4 KB | |
| 커널 소켓 버퍼 | RSS에 안 잡힘 | `/proc/net/sockstat`로 별도 공개 필요 (공정 비교) |

### 1.2 전달 1건의 경로 (고부하)

```
발행자 task: decode → policy → dispatch → publish_room
  └ sessions_in(room): DashSet 순회 = 샤드 락 128회 + 세션 키 String 복제 N개
  └ 수신자마다: 레지스트리 SipHash 조회 → Connection 복제(Arc 2개) → try_send (원자 연산 + 필요 시 깨움)
수신자 task (다른 코어일 수 있음): 깨어남 → recv → OutFrame → axum Message 변환(할당+복사) → WS 프레이밍 → write 시스템 콜
```

## 2. 레지스트리와 룸: 문자열 키·중첩 동시성 맵 제거

### 2.1 ID와 핸들

```rust
/// 내부 식별자는 정수. 문자열은 경계(설정·프로토콜)에서 한 번만 인터닝한다.
struct TenantId(u32);
struct RoomId(u32);        // (TenantId, 룸 이름) → RoomId, 테넌트 범위 인터너
struct ConnId { idx: u32, gen: u32 }   // slab 인덱스 + 세대(재사용 시 ABA 방지)

/// 발행자가 수신자에게 넣을 때 필요한 것 전부. 세션 task와 공유.
struct SessionShared {
    id: ConnId,
    tenant: TenantId,
    outbox: Outbox,               // §3.1
    hot: HotSlot,                 // §3.2 (T0-3)
    close: CloseSignal,           // §3.3
}
type SessionHandle = Arc<SessionShared>;
```

- 레지스트리: `ConnId → SessionHandle`은 샤드 slab(`Vec<Option<SessionHandle>>` × 샤드, 각 `Mutex`). 조회가 해시 없이 인덱스 접근.
- 사용자 색인: `DashMap<(TenantId, UserId), SmallVec<[ConnId; 4]>, FxBuildHasher>` — 안쪽은 일반 컬렉션, 바깥 엔트리 락이 직렬화한다(C5 "빈 집합이면 제거"는 `remove_if`로 유지).
- **효과**: `DashSet` 제거로 세션당 약 7 KB, 사용자당 약 14 KB 절감. 문자열 이어 붙인 키가 사라져 **테넌트 간 키 충돌**도 원천 제거(테넌트 ID 문자 제한은 그 전에 즉시 적용).

### 2.2 룸 멤버십: 읽기용 스냅샷

발행은 매우 잦고 입장·퇴장은 드물다. 그래서 팬아웃은 락 없이 스냅샷을 읽게 한다.

```rust
struct Room {
    members: ArcSwap<Members>,      // 발행: load() 한 번(원자 연산 1회), 락 없음
    gov: Mutex<RoomGovernance>,     // 입장·퇴장·한도 계산 전용 (발행 경로에서 안 건드림)
}
struct Members { handles: Box<[SessionHandle]> }
```

- 입장·퇴장: `gov` 락 안에서 새 `Members`를 만들어 `store`(copy-on-write, O(룸 인원)). 1,000명 룸 입장 1회 ≈ 수 µs — 입장 빈도에서는 문제없다.
- 아주 큰 룸(1만 명 이상)은 멤버를 청크(예: 256명 단위)로 나눠 청크만 다시 만든다(§6의 샤드별 팬아웃과 합류).
- 거버넌스 색인(사용자↔룸 참조 카운트, 룸·사용자 한도)은 `gov`와 테넌트 카운터에만 둔다. **발행 경로와 분리**.
- 발행: `for h in members.load().handles.iter() { h.deliver(&frame) }` — 수신자당 조회·해시·문자열 복제 0, `Arc` 복제 0(빌려서 씀).
- 목표: 발행자 측 수신자당 비용 약 200 ns → **≤ 50 ns**.

### 2.3 해셔

남는 내부 맵은 `FxHash`(정수 키) 또는 `ahash`. 클라이언트가 고르는 문자열 키(룸 이름 인터닝)만 HashDoS 방지를 위해 키 있는 해셔(`ahash` 무작위 시드)를 쓴다.

## 3. 송신 경로

### 3.1 Outbox (신뢰 큐)

- 지금의 tokio `mpsc`는 의미상 맞다(깨움도 이미 합쳐진다: 수신자가 깨어 있으면 추가 깨움 없음). 비용은 생성 시 32슬롯 블록(약 1.3 KB).
- 1단계: 유지. 2단계(프로파일 후): `Mutex<VecDeque<OutFrame>>` + `AtomicBool scheduled` + `Notify` 기반 자체 큐 — 비었을 때 0 B, 깨움은 `scheduled`가 false→true일 때만. 큐 용량 한도와 C9(자기 큐를 기다리지 않음), C1(가득 차면 Reliable은 종료) 의미는 그대로.

### 3.2 Hot 슬롯 (T0-3)

- 설계 §4.2 그대로: `(sender, svc, key) → Bytes` 최신값 + 키 없는 짧은 FIFO, 상한. 구현은 세션별 `Mutex<SmallMap>` + `scheduled` 플래그 하나. 발행자는 덮어쓰기만(블로킹 없음), 깨움은 첫 번째에만.
- 틱 묶음 송신은 §3.4의 쓰기 합치기와 같은 경로를 쓴다.

### 3.3 종료 신호

`mpsc::channel::<CloseSpec>(1)`(약 1.8 KB) → `Mutex<Option<CloseSpec>>` + 세션 task의 `Notify`(수십 B). 우선순위(킥이 메시지보다 먼저)는 이벤트 루프의 `select!` 순서로 지금처럼 보장.

### 3.4 쓰기 합치기: 버퍼 없이

- 문제: T0의 `recv_many(&mut Vec, 64)` 방식은 `Vec`이 연결마다 상주하고 부하 시 커진 채 남는다(A/B: +2.8~5.3 KB/연결).
- 교체: `SessionTx`를 `feed(frame)` / `flush()`로 쪼갠다. 루프는 `recv()`로 첫 프레임 → `feed` → `try_recv()`로 최대 63개를 바로 `feed` → `flush` 한 번. 중간 버퍼 없음. WebTransport datagram 구현은 `feed`가 곧 송신, `flush`는 no-op.
- 남는 버퍼는 tungstenite `out_buffer`(한 번 커지면 유지). §4에서 자체 프레이밍으로 없앤다.

### 3.5 사전 인코딩 프레임과 vectored write (가장 큰 송신 레버)

- 서버 프레임은 마스킹하지 않으므로 `[FIN|opcode][len][payload]` 전체가 수신자와 무관하다. `OutFrame`이 **완성된 와이어 프레임**(`Bytes`)을 들고 다니게 하면, 수신자 task는 복사·인코딩 없이 그대로 쓴다.
- 여러 프레임을 한 번에: `writev`(`AsyncWrite::poll_write_vectored`)로 공유 `Bytes` 조각들을 시스템 콜 하나로 보낸다 — 연결별 쓰기 버퍼도 필요 없다. 부분 쓰기는 남은 조각의 오프셋만 연결 상태에 기록.
- TLS를 게이트웨이에서 끝내면(WSS) 연결마다 암호화하므로 바이트 공유가 깨진다 → 방송형 배포는 **LB에서 TLS 종단**을 권장하고, 게이트웨이 TLS는 kTLS(커널 TLS, rustls + `ktls`)로 사용자 공간 복사를 줄이는 선택지를 둔다(검증 필요).
- 전제: axum/tungstenite는 이 수준의 제어를 노출하지 않는다 → §4.

### 3.6 쓰기 타임아웃을 막힐 때만 (신규, 측정 5.6%)

- 지금: 쓰기 묶음마다 `tokio::time::timeout(writer_timeout, …)`으로 타이머를 하나 등록하고 지운다(`Sleep::poll`, `Timeout` drop, 시계 읽기). 소켓 버퍼에 여유가 있으면 쓰기는 즉시 끝나므로 타이머는 거의 항상 헛돈다.
- 교체: 먼저 타이머 없이 한 번 폴링하고, `Pending`일 때만 마감을 건다. 세션마다 `Sleep` 하나를 재사용(`reset`)하면 등록·해제도 없다. 느린 소비자 보호(C9 이후의 slow consumer 종료)는 그대로.

### 3.7 수신자마다 UTF-8을 다시 검사하지 않기 (신규, 측정 2.0%)

- 지금: `Utf8Text`는 생성 시 한 번 검증했는데, `to_message`가 axum `String`을 만들려고 `String::from_utf8_lossy`로 **수신자마다 다시 검증**하고 복사한다.
- 1단계: axum 0.8의 `Utf8Bytes`(검증된 `Bytes`)로 넘기면 검증·복사가 모두 사라진다(§4 1단계와 같은 작업). 그 전에 할 수 있는 것은 검증 없는 변환인데 `unsafe`가 필요하므로, 0.8 전환에 합친다.

## 4. 전송 구현: 자체 WebSocket 프레이밍 (ADR 필요)

| fastwebsockets | 낮음 | 연결별 버퍼 | 제한적 | 평가 대상 |
| **자체 서버 측 프레이밍** (tokio `TcpStream` 직접) | 0 | **유휴 0** (§4.1) | **가능** | RFC 6455 서버 측만: 클라이언트 프레임 마스크 해제, 서버 프레임 무마스크, 조각·제어 프레임, close 핸드셰이크, 크기 한도. 퍼징 필수 |

권장 순서: ① axum 0.8로 수신자당 복사 제거(작고 안전) → ② 프로파일에서 시스템 콜·버퍼가 여전히 지배하면 자체 프레이밍으로. 업그레이드 핸드셰이크·admission은 hyper/axum에 두고, 업그레이드된 소켓만 자체 코덱이 맡는다(지금 `ws_upgrade` 구조 그대로).

### 4.1 유휴 연결의 읽기 버퍼를 0으로

- 소켓을 readiness 방식으로 읽는다: `stream.readable().await` → **워커 스레드 공용 버퍼**(스레드 로컬 64 KB)에 `try_read` → 완성된 프레임을 그 자리에서 마스크 해제·디코드.
- 완성되지 않은 프레임 꼬리만 연결별 작은 `Vec`에 옮긴다(대부분의 연결은 대부분의 시간에 0 B).
- Hot 페이로드는 팬아웃이 버퍼보다 오래 살아야 하므로 한 번만 `Bytes`로 복사(이미 지금도 디코드 시 1회 복사).
- 효과: tungstenite 8 KB 제거. §2 + §3.3 + §3.4와 합쳐 **유휴 연결 ≤ 8 KB** 목표의 근거.

## 5. 타이머: 연결마다 깨우지 않기

- 지금: 세션마다 `interval` 2개(ping 20 s, idle 검사 **1 s**). 10만 연결 = 초당 10만 번 깨움, 대부분 할 일 없음.
- 교체: 세션은 `last_activity`를 `AtomicU32`(거친 시계, 아래)로만 기록한다. **샤드마다 스위퍼 task 하나**가 1초마다 자기 샤드의 세션을 훑어 ① 유휴 초과 → `CloseSignal`, ② ping 기한 도래 → Outbox에 Ping을 넣는다. 10만 세션 스캔은 원자 읽기 10만 번(수백 µs)으로 끝난다.
- 거친 시계: 전역 `AtomicU32` 밀리초를 10 ms마다 갱신하는 task 하나. 메시지마다 `Instant::now()`를 부르지 않아도 된다(레이트리밋 버킷은 정밀도가 필요하면 그대로 `Instant`).
- 효과: 연결당 타이머 항목 2개와 그 깨움 제거.

## 6. 런타임과 코어 사용

### 6.1 지금 구조의 한계

tokio 다중 스레드 런타임 + 작업 훔치기. 큰 룸 팬아웃은 발행자 task 하나가 N명에게 넣고, 수신자 task는 여러 코어에 흩어져 깨어난다 → 전달마다 코어 간 깨움.

### 6.2 샤드별 팬아웃 (측정으로 필요가 확인되면)

- 연결을 샤드(코어)에 고정: `SO_REUSEPORT` 리스너를 코어마다 하나, 샤드마다 단일 스레드 런타임.
- 룸 멤버를 샤드별로 나눠 보관. 발행 = 멤버가 있는 **샤드마다 한 번** 넘기고(코어 간 메시지 N → 샤드 수), 각 샤드가 자기 소켓들에 쓴다.
- 비용: 연결 수가 샤드 사이에 고르지 않으면 불균형. 작업 훔치기를 포기하는 대신 캐시 지역성을 얻는다. 큰 결정이라 ADR + 프로토타입 측정 후.
- 그 전 단계로, 큰 룸(예: 256명 초과)만 팬아웃을 별도 task로 분리해 발행자 task의 꼬리 지연을 끊는 것을 먼저 시험한다.

## 7. 레이트리밋

- 연결 단위: 지금처럼 세션 소유(락 없음). 유지.
- **테넌트 단위: 전역 `Mutex<TokenBucket>` → GCRA를 `AtomicU64` 하나로.** 상태 = "이론적 도착 시각(TAT)". `allow`: `tat' = max(tat, now) + 간격`, `tat' − now ≤ 버스트 허용치`면 CAS로 확정. 락 없음, 정확도 같음. 고부하에서 여러 코어가 같은 원자 변수를 CAS하는 경합은 남으므로, 필요하면 코어별 토큰 할당(주기적 재분배)으로 확장.

## 8. 메트릭

- 메시지당 라벨 `Vec` 할당·정렬(275 ns) 제거: admission 시 테넌트별 **핸들 구조체**(`Arc<TenantMetrics>`: 필요한 카운터·히스토그램 필드)를 해석해 세션에 둔다. 메시지 경로는 필드 접근 + 원자 연산.
- **코어별 샤딩**: 메시지마다 증가하는 카운터(전달 수, 디스패치 히스토그램)는 `[CachePadded<AtomicU64>; 샤드 수]`로 나누고 `/metrics` 렌더 시 합산. 216만/s에서 원자 변수 하나를 모든 코어가 증가시키면 캐시 라인 경합이 생긴다.
- 테넌트 수천 개: 테넌트 라벨은 상위 N + `_other`로 제한하는 옵션(카디널리티).

## 9. 할당자와 커널

- **전역 할당자**: mimalloc 또는 jemalloc. 다중 스레드에서 작은 할당이 많은 서버에 효과가 크고, RSS 반납·단편화 특성도 다르다(지금 BENCHMARKS의 "RSS가 줄지 않음"과 관련). 한 줄 변경이라 가장 먼저 측정할 가치가 있다(의존성 추가 → 네트워크로 크레이트를 받아야 하므로 사전 확인).
- 소켓: `SO_SNDBUF`/`SO_RCVBUF`를 작게 고정하면 커널 메모리가 줄지만 처리량과 맞바꾼다 → 설정으로 노출하고 기본값은 커널 자동 조정. 커널 소켓 메모리를 공정 비교에 포함(`/proc/net/sockstat`).
- 수용: `SO_REUSEPORT` 다중 accept는 §6.2와 함께.
