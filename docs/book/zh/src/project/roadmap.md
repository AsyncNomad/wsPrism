# 路线图

wsPrism 的目标是：大公司可以放心运行，小团队不必 fork 就能按需定制，而且可以用测量证明比现有网关更快。本章说明它目前走到了哪里、接下来做什么。更详细的工作计划见 [`docs/ROADMAP.md`](https://github.com/AsyncNomad/wsPrism/blob/main/docs/ROADMAP.md)。

## 当前进展

| 领域 | 状态 |
|---|---|
| 准入 | 检查流水线、Origin 策略、可信代理、凭证位置、协议 v1 与 v2 |
| 集成 | 认证链（一次性票据、JWT 与 JWKS、连接代理、插件）、服务端 API、RPC 代理、JavaScript SDK、示例应用 |
| 扩展 | 通过 `Gateway::builder` 添加服务和认证器 |
| 历史与扩展性 | 房间历史与恢复；支持 Sentinel 和 TLS 的 Redis 集群（实验性） |
| 运维 | 带脱敏的 JSON 日志、来自环境变量的配置、Prometheus 指标、无损排空、容器镜像 |
| 加固 | 随机浸泡测试与混沌测试、fencing、过载保护、发布前的缺陷排查 |
| 质量 | 约 270 个 Rust 测试、SDK 与端到端测试、5 个模糊测试目标、CI 中的依赖审计 |

## 0.1.0 之后

大致按优先级排列：

- **热加载**租户策略，无需重启。
- Hot 通道的 **WebTransport** 支持：作为小型交互房间的可选方案，以 WebSocket 兜底；同时加入**服务端对等节点**，让权威游戏服务器以受信任的长期成员身份接入网关。
- 当需要超过单个 Redis 核心的历史吞吐量时，**把房间流量分散到多个 Redis**（ADR 0013 中设计已采纳）。
- **更多 SDK：** Unity（C#），然后是 Dart。
- **运维：** OpenTelemetry、基于角色的管理 API、Helm chart、UDP 负载均衡指南。
- 在 Ext 通道上以沙箱方式运行租户级逻辑的 **WebAssembly 插件**。
- **迈向 1.0：** CI 中的 semver 检查、贡献指南、更多示例（多人游戏、协作光标）、外部安全审计。

## wsPrism 不会成为什么

- **游戏服务器。** 它站在你的游戏服务器前面（无论用什么语言写），只负责搬运流量。
- **消息队列或数据库。** 历史消息只用来弥合重连的间隙，持久数据请放在你自己的存储里。
- Socket.IO、Pusher 等其他协议的**兼容层**。
