# 로드맵

wsPrism의 목표는 대기업이 믿고 운영할 수 있고, 작은 팀이 포크 없이 원하는 대로 바꿔 쓸 수 있으며, 기존 게이트웨이보다 측정 가능하게 빠른 실시간 게이트웨이입니다. 이 장은 지금 어디까지 왔고 다음에 무엇을 할지 정리합니다. 더 자세한 작업 계획은 [`docs/ROADMAP.md`](https://github.com/AsyncNomad/wsPrism/blob/main/docs/ROADMAP.md)에 있습니다.

## 지금 위치

| 영역 | 상태 |
|---|---|
| 입장 검사 | 검사 파이프라인, Origin 정책, 신뢰 프록시, 자격 증명 위치, 프로토콜 v1·v2 |
| 연동 | 인증 사슬(1회용 티켓, JWT와 JWKS, connect 프록시, 플러그인), 서버 API, RPC 프록시, JavaScript SDK, 예제 앱 |
| 확장 | `Gateway::builder`로 서비스와 인증기 추가 |
| 이력과 확장성 | 룸 이력과 복구. Sentinel과 TLS를 지원하는 Redis 클러스터(실험적) |
| 운영 | 민감 정보를 가린 JSON 로그, 환경 변수 설정, Prometheus 메트릭, 무손실 드레인, 컨테이너 이미지 |
| 견고화 | 무작위 soak와 카오스 시험, 펜싱, 과부하 보호, 릴리스 전 결함 전수 탐색 |
| 품질 | Rust 테스트 약 270개, SDK와 종단 간 시험, 퍼징 대상 5개, CI의 의존성 감사 |

## 0.1.0 이후

대략 우선순위 순서입니다.

- 재시작 없이 테넌트 정책을 다시 읽는 **핫 리로드**
- Hot 레인용 **WebTransport**. 작은 인터랙티브 룸을 위한 선택지로 넣고 WebSocket을 대안으로 둡니다. 함께 **서버 피어**도 넣습니다. 권위 있는 게임 서버가 신뢰받는 장기 멤버로 게이트웨이에 붙는 방식입니다.
- Redis 코어 하나를 넘는 이력 처리량이 필요해지면 **룸 트래픽을 여러 Redis에 나누기**(ADR 0013에서 설계 채택)
- **SDK 추가:** Unity(C#), 그다음 Dart
- **운영:** OpenTelemetry, 역할 기반 관리 API, Helm 차트, UDP 로드밸런싱 안내
- Ext 레인에서 테넌트별 로직을 샌드박스로 돌리는 **WebAssembly 플러그인**
- **1.0을 향해:** CI의 semver 검사, 기여 안내, 예제 추가(멀티플레이, 협업 커서), 외부 보안 감사

## 앞으로도 되지 않을 것

- **게임 서버.** 어떤 언어로 만들었든 게임 서버 앞에 서서 트래픽을 나를 뿐입니다.
- **메시지 큐나 데이터베이스.** 이력은 재접속의 틈을 메울 뿐이고, 영속 데이터는 내 저장소에 둡니다.
- Socket.IO, Pusher 같은 다른 프로토콜의 **호환 계층**
